# 프로젝트 팩트시트 — 청각장애인 위험 소리 방향 감지 안경

> 발표자료·문서 작성용 사실 정리 (2026-07-20 기준).
> 모든 수치는 **실측값**이며 출처는 저장소 커밋 메시지에 상세 기록되어 있음.

---

## 1. 한 줄 정의

**안경에 장착한 4개 마이크로 위험한 소리가 "어디서" 났는지 360° 방향을 찾고,
AI가 "무슨 소리"인지 분류해, 화면에 방향+종류를 함께 표시하는 웨어러블 시스템.**

## 2. 문제 정의 (개발 배경)

- 청각장애인에게 실질적 위험은 "소리가 났다"보다 **"어디서 났는지 모른다"** — 자동차 경적, 뒤에서 오는 오토바이, 화재경보의 위치
- 기존 제품 조사 결과:
  - Taptic 등 보급형 알림 기기: **단일 마이크 → 방향 정보 없음**
  - Starkey/Phonak 등 고급 보청기: 방향성 있으나 **고가이며 사용자가 원하는 소리를 직접 등록 불가**
- 따라서 **저비용 + 방향 + 소리 종류 분류 + 사용자 커스텀 등록**의 조합이 비어 있음 → 본 프로젝트의 목표

## 3. 시스템 구성

```
[안경형 센서 노드]                    [노트북 = 연산 서버]         [표시 장치]
 INMP441 마이크 ×4 (17cm 십자)         serve.py 중계 서버           브라우저 대시보드
 MPU-9250 IMU (자이로)         WiFi     YAMNet 소리 분류      SSE    PC / iPad / 폰
 ESP32-S3-WROOM-1 N16R8    ─────────>  분류×방향 융합       ─────>  (동시 다중 시청)
 (TDOA 방향 계산, 오디오 스트리밍)      커스텀 소리 지문 매칭
```

- **역할 분담**: 실시간성이 필요한 방향 계산은 기기에서(마이크로초 단위 시간차), 연산량이 큰 AI 분류는 노트북에서
- **전송**: WiFi TCP (라인 단위 JSON) — 오디오 46KB/s + 이벤트 2KB/s ≈ **0.39Mbps** (WiFi 실효 대역의 1~2%)
- **USB 폴백**: WiFi 장애 시 자동으로 USB 시리얼 경로로 전환 (디버깅·안전망)

### 하드웨어 사양
| 항목 | 값 |
|------|-----|
| MCU | ESP32-S3-WROOM-1 N16R8 (16MB Flash / 8MB PSRAM) |
| 마이크 | INMP441 I2S MEMS ×4, 17cm 십자 배열 (안경 프레임 장착) |
| 샘플링 | 48kHz / 24bit, I2S 2포트(X쌍·Y쌍) 동시 수신 |
| IMU | MPU-9250 계열 (자이로 Z축, I2C 400kHz) |
| 통신 | WiFi 2.4GHz TCP(:9000) + mDNS(doa-node.local) |
| 전원 | USB 5V (보조배터리로 완전 무선 동작 가능) |

### 소프트웨어 스택
- 펌웨어: C++ / Arduino-ESP32 (PlatformIO), 자체 구현 1024점 radix-2 FFT
- 서버: Python 3.11, TensorFlow + TensorFlow Hub (YAMNet), 표준 라이브러리 HTTP/SSE
- 대시보드: 순수 HTML/SVG/JS (프레임워크 무의존, 단일 파일)
- 오픈소스 사용: **YAMNet** (Google, Apache 2.0, AudioSet 521클래스 사전학습) ← 참가신청서 명시 필요

## 4. 핵심 알고리즘

### (1) 방향 감지 — TDOA + GCC-PHAT
- 마주보는 마이크 쌍의 **도달 시간차(TDOA)**로 각 축 성분을 구하고 `atan2`로 360° 합성
- 시간차는 **0.125 샘플(2.6µs)** 격자로 탐색 후 포물선 보간 — 17cm 간격에서 물리 최대 지연 ±23.8샘플
- **GCC-PHAT**: 주파수별 크기를 1로 정규화해 위상만 투표시킴 → 잔향이 직접음보다 커도 직접음이 이김
  (일반 상관은 "가장 큰 에너지 경로"를 찾기 때문에 반사음에 피크를 빼앗김)
- 대역 제한 550~2600Hz (공간 앨리어싱 회피 + 저주파 소음 차단)

### (2) 온셋 정렬 (선행음 효과 응용) — 본 프로젝트의 핵심 개선
- 직접음은 반사음보다 **항상 2~8ms 먼저** 도착 (사람이 잔향 속에서도 방향을 아는 원리)
- 1.33ms 블록 에너지로 "조용→급상승" 지점을 찾아 **그 직후 5.3ms 창만** 상관에 사용
- 온셋 프레임만 이벤트 판정 자격을 부여 → **반사음 오판정 원천 차단**
- 실측 효과: 좌우가 뒤섞이던 문제 해소 (박수의 절반이 반사 프레임을 먼저 래치하던 현상)

### (3) 신뢰도 게이트 3종
| 게이트 | 목적 | 값 |
|--------|------|-----|
| 적응형 에너지 | 배경소음 바닥을 EMA로 학습, 과민 반응 차단 | max(12000, 2.5×바닥) |
| 포화(클리핑) | 찌그러진 파형의 엉터리 시간차 배제 | 24bit 85% 초과 샘플 1.5%↑ |
| 기계 진동 | 표면 접촉으로 전달된 진동 배제 | rms > 120,000 |
- 추가: 물리적 최대 지연 초과 lag 기각, 불응기 510ms(반사 재발화 흡수), 서버측 반사 플립 가드(1.2초)
- **지속 소음원 습관화**: 같은 방향 10초 15회↑ 반복 시 자동 억제 (열린 창문 교통소음으로 실증)

### (4) 소리 분류 × 방향 융합
- 마이크 1개의 광대역 원신호를 48k→16kHz 데시메이션 후 base64 JSON으로 전송
- YAMNet이 0.975초 창을 0.5초마다 분류 → 상위 3개 라벨
- 서버가 최근 2초 방향 이벤트와 결합 → `alert`(위험) / `sound`(일반) 이벤트 발행
- 위험 목록: 화재경보, 사이렌 4종, 경적, 비명, 깨지는 소리, 경보음, 개 짖음 등

### (5) 사용자 커스텀 소리 등록 (few-shot, 재학습 없음)
- 6초 녹음 중 **에너지가 가장 큰 1초**만 잘라 YAMNet 임베딩(1024차원) 추출 → 지문 저장
- 실시간 임베딩과 코사인 유사도 ≥ 0.72면 인식, 같은 이름 반복 등록 시 테이크 축적(최대 10개)
- 침묵 오염 방지: 등록 시 최소 세기 검사, 인식 시 조용한 창은 비교 자체를 생략

### (6) IMU 회전 보정 (착용형 필수)
- 자이로 yaw를 적분해 **모든 방향 이벤트에 발생 시점 자세를 동봉**
- 대시보드가 세계좌표로 고정 → **기기(고개)가 돌아가도 화살표가 소리 난 방향을 계속 지목**
- 정지 자동 재보정(2초 창 ±1dps 이내면 바이어스 갱신) → RST 없이 드리프트 자가 치유
- 영점 버튼: 착용 후 정면에서 한 번 누르면 그 자세가 기준(0°)
- 회전 중 발생한 소리도 정확 (측정~발행 지연 20~85ms → 고속 회전 시에도 오차 2~8°)

## 5. 실측 성과

| 항목 | 결과 |
|------|------|
| 방향 정확도 (평면 내 박수) | **오차 ±3°** (기대 180° → 실측 182.7°) |
| 4방향 판정 | 좌/우/위/아래 전부 실측 합격 (물리 최대 지연 ±23.8 근접값 관측) |
| 화재경보 분류 | **0.87~0.98** (8초 재생 내내, T-3 패턴 정지 구간까지 추적) |
| 오탐 | 조용한 20초 동안 이벤트 **0건** (게이트 조정 후) |
| 커스텀 소리 인식 | 유사도 **0.74~0.90**, 다른 소리(화재경보) 재생 시 오탐 0 |
| 실사용 검증 | 쿠쿠 밥솥 완료음 등록 후 실제 인식 성공 |
| 반응 지연 | 방향 ~0.25초, 분류 ~1.5초 (분석창 0.975초 포함) |
| 최적 인식 거리 | 30cm ~ 1.5m |
| 무선 전송 | 오디오+이벤트 전체 무선 가동, 끊김 시 3초 내 자동 재접속 |
| 연산 부하 | 프레임당 FFT+조향 2~5ms (예산 21ms), RAM 21% |

## 6. 개발 여정 — 문제 발견과 해결 (발표 차별화 포인트)

> 모든 사건은 실측 데이터로 규명하고 커밋 메시지에 근거를 기록함.

| 문제 | 증상 | 원인 규명 | 해결 |
|------|------|----------|------|
| 신뢰도 붕괴 | conf 0.01~0.03 | 저주파 소음/클럭 앨리어싱 | 밴드패스(이동평균 차) |
| 방향 널뜀 | 열쇠 소리 방향 산포 | 공간 앨리어싱(>2.9kHz) | 대역 상한 제한 |
| 원거리 붕괴 | 2~4m에서 방향 무의미 | **잔향이 직접음보다 커짐**(임계거리) | GCC-PHAT 도입 |
| 좌우 뒤섞임 | 박수 절반이 반대편 판정 | 반사 프레임을 먼저 래치 | **온셋 전용 판정** |
| 방향 고정 오판정 | 어디서 쳐도 같은 두 방향 | **책상 진동**(목재 4000m/s가 공기 343m/s보다 먼저 도착) | 진동 게이트 + 절연 운용 |
| 상시 오탐 | 조용한데 이벤트 30건/20초 | 열린 창문 교통소음 | 적응형 게이트 + 습관화 필터 |
| 커스텀 오탐 | 등록 후 계속 인식 | 6초 녹음에 침묵이 섞여 지문 오염 | 최대 에너지 1초만 사용 |
| 탐지 5~10초 지연 | 전체 반응 느림 | pyserial readline이 1바이트씩 읽어 버퍼 누적 | 일괄 읽기로 교체 |
| 채널 간헐 사망 | 됐다 안 됐다 반복 | **3.3V-데이터선 간헐 쇼트** | 배선 수리 |

**진단 방법론도 성과**: 채널 확인은 마이크 직접 탭(레벨 스파이크로 위치↔채널 매핑), 방향 확인은 박수(바람·문지르기는 국소 잡음이라 판정 불가) — 이 원칙을 세운 뒤 디버깅 속도가 크게 개선됨.

## 7. 정직한 한계

- **순음(사이렌·휘파람) 방향 정확도**가 광대역 소리(박수·경보음)보다 낮음 — PHAT은 여러 주파수의 교차 투표로 작동하는데 순음은 투표자가 적기 때문
- 원거리(2m 이상)는 게이트 문턱과 트레이드오프 — 현재는 오탐 억제를 우선해 조정
- 프레임이 딱딱한 표면에 닿으면 진동 오염 (착용 시에는 머리가 절연체 역할이라 문제 없음)
- 분류는 노트북 연산에 의존 (온디바이스 아님)
- 마이크 쌍 간 감도 차이(제조사 상이)는 게인 보정으로 대응 — 방향 계산 자체는 크기와 무관해 영향 없음

## 8. 확장 로드맵

1. **진동 햅틱 알림** — 안경다리 좌우 진동모터 2개로 방향 전달(앞/뒤는 패턴 구분). 화면을 보지 않아도 되는 것이 청각장애인 UX의 핵심
   - 선행연구: feelSpace naviBelt(시각장애인용 촉각 방향 벨트)에서 유효성 검증됨 → 본 프로젝트는 이를 **청각장애인의 실시간 음원 방향 인지**에 적용
2. **BLE 저전력 전환** — 오디오 8kHz+ADPCM 압축(약 4KB/s)으로 BLE 대역에 수용, 소비전력 약 10배 절감(150mA→15mA)
3. **온디바이스 분류** — TinyML로 기기 내 분류 시 노트북 의존 제거
4. **SoftAP 모드** — 공유기 없는 야외에서 기기 자체 핫스팟으로 동작
5. **스마트폰 앱** — 대시보드를 앱으로, 진동은 폰 또는 전용 모듈로
